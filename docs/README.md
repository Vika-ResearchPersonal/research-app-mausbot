# Documentation

| Folder | Contents | Template |
|---|---|---|
| `prd/` | Product Requirements Documents | `templates/prd.md` |
| `tsd/` | Technical Specification Documents | `templates/tsd.md` |
| `design/` | UI and component design | `templates/design.md` |
| `adr/` | Architecture Decision Records | `templates/adr.md` |

## Flow

1. PRD: problem, users, requirements, success measures.
2. TSD: components, data model, interfaces, security, rollout. Written after the PRD is approved.
3. Design: only when the feature has UI.
4. Issues: each links the TSD section it implements.

Status values: `draft`, `in review`, `approved`, `superseded`.
